# 设备上行状态翻译 需求文档

## 1. 背景与问题

在语音硬件（AIoT）场景下，智能体需要「查询设备当前状态」并把结果喂给大模型，用于回答用户（如「我的床现在是什么模式？」「音量多大？」）。

调用设备状态查询工具（如 `iot_get_device_shadow` / 获取设备影子状态）后，设备回的是一段**原始上行状态 JSON**，例如：

```json
{
  "success": true,
  "code": 200,
  "message": "操作成功",
  "data": {
    "bedsteadStatus": 2,
    "underBedLight": 1,
    "volume": 60,
    "mattress": { "left": { "monitor": { "heartRate": 66 } } }
  },
  "timestamp": 1785334704485
}
```

**核心痛点**：这份 JSON 是面向设备协议的裸数据，模型无法理解其业务含义——

- 字段名是英文/缩写（`bedsteadStatus`、`underBedLight`），模型不知道对应什么功能；
- 枚举是编码（`bedsteadStatus: 2`），模型不知道 `2` 代表「平躺模式」；
- 夹杂大量无业务价值的协议外壳字段（`success`、`code`、`message`、`timestamp`），干扰模型判断。

若直接把原始 JSON 拼进提示词，模型的理解准确率低、易产生错误回答。因此需要在数据进入模型前，**把上行状态翻译成模型可理解的自然语言文本**。

## 2. 目标

- 将设备上行状态 JSON 翻译为一段模型友好的自然语言状态描述；
- 翻译规则由运营人员在配置阶段一次性配置，工程执行时按实时上报值自动渲染；
- 翻译能力**独立于指令集**，只消费上行数据，不与下行控制契约耦合。

## 3. 概念澄清（架构约束）

| 概念 | 含义 | 数据方向 |
| --- | --- | --- |
| 指令集 | 下发给设备的控制契约（写设备） | 下行数据 |
| 接口返回 | 设备实际上报的状态 | 上行数据 |

**约束**：状态翻译只处理「上行数据」，须独立于指令集单独配置，不复用指令集的字段定义。

## 4. 实现方式

在**调用工具**能力中，为支持状态上报的工具增加一项「运行时配置」。运行时配置存放该工具执行时的额外处理规则（本需求即：状态码转译模板、字段映射等）。

具体交互：

- **入口**：提示词编辑区「任务规划器」行右侧、「编写教程」左侧的「工具配置」文字链接，点击打开工具配置面板抽屉（宽 820px）。
- **面板采用草稿编辑态**：编辑操作先写入内部 `draft` 对象，点「确定」经校验后才提交到 `AC.usedTools`；未确定即切走则草稿丢弃。
- **已添加工具行** `AC.usedTools`：对象数组 `[{id, name, desc, tool}]`，行 id 由 `acGenToolId()` 生成。列表双行展示（自定义名称 + 描述），初始态自动选中第一个工具。
- **工具面板与提示词不做联动**：加入/移除工具都不会改动提示词；运营需在提示词中**自行书写**该工具的调用说明。
- **运行时配置区始终展示**（无论是否已选择工具），含「解析并配置翻译」入口与配置文本框。
- 点击「解析并配置翻译」，打开**设备状态翻译配置弹窗**（回调式：`acDeviceStateModal(rowId, onDone, dispNameArg)`），生成结果通过 `onDone(out)` 回调写回草稿 `draft.runtime`，不再直接操作 DOM 或全局配置。
- 运营配置完成后，点击弹窗底部「生成翻译」，生成的翻译配置通过回调写回运行时配置文本框并同步到 `AC.toolRuntimeConfig[行id]`。

## 5. 配置流程（弹窗内两步）

### 步骤 1：查看并解析上行 JSON

- 输入 `deviceId` 和 `token`（必填），点击「获取上行状态」拉取该设备的实时上行状态；
- 拉取到的上行 JSON 以**只读**文本框展示（当前为模拟示例数据，仅供解析/配置参考，不支持手动编辑）；
- 拉取成功后自动解析并生成步骤 2 的配置表格，同时显示底部「生成翻译」按钮。

### 步骤 2：解析后配置表格

解析结果以**树形表格**逐字段展示，支持嵌套对象的折叠/展开。每个叶子字段可配置：

| 列 | 说明 |
| --- | --- |
| 上行字段 | 字段的完整点路径（如 `data.mattress.left.monitor.heartRate`），父节点（对象容器）带折叠加/减号 |
| 原始值 | 本次上报的实际值，供配置时参考 |
| 标识含义（显示名） | 运营填写的业务名称，如「预设模式」「床底灯」 |
| 值类型 | 请选择 / 枚举 / 数值 / 开关 / 文本 / 数组 |
| 枚举映射 / 翻译结果 | 值类型为枚举/开关时，配置「编码 → 含义」映射（可增删映射项，如 `2 → 平躺模式`），并实时展示「当前值 → 命中含义」；数值/文本/数组直接取值透传 |

**无业务价值字段**：`success`、`code`、`message`、`timestamp` 等协议外壳字段自动置灰，不可配置、不参与翻译；父节点（对象容器）本身也不可配置，仅用于层级折叠。

### 状态持久化（草稿）

- 弹窗仅**初始态**无 `deviceId`/`token`；只要点击过一次「获取上行状态」，本工具行的 `deviceId`、`token`、上行 JSON 及表格配置即按**行 id** 保存为草稿（`AC.deviceStateDraft[行id]`）；
- 重新打开该工具行的弹窗时自动回填草稿并重建配置表格，运营编辑（改显示名/值类型/映射项、折叠等）都会即时更新草稿。

## 6. 翻译配置生成规则（写回内容）

点击「生成翻译」，仅对**已填写显示名且已选值类型**的字段生成 Jinja2 模板表达式，并汇总枚举/开关的映射表，最终写回一段 **JSON 结构**（而非纯模板字符串）。

**表达式规则**：

- **数值 / 文本 / 数组**：直接取值 → `{{ data.xxx }}`
- **枚举 / 开关**：走映射变量 → `{{ data_xxx_map[data.xxx | string] }}`（映射变量名 = 点路径的 `.` 替换为 `_` 再加 `_map` 后缀，避免 Jinja 变量名非法）

**写回 JSON 结构**：

```json
{
  "postHandler": "templateRender",
  "templateRender": {
    "mappings": {
      "data_bedsteadStatus_map": { "1": "坐姿", "2": "平躺模式", "3": "零重力" },
      "data_underBedLight_map": { "0": "关闭", "1": "开启" }
    },
    "template": "> **当前设备状态**：预设模式={{ data_bedsteadStatus_map[data.bedsteadStatus | string] }} 床底灯={{ data_underBedLight_map[data.underBedLight | string] }} 音量大小={{ data.volume }}"
  }
}
```

说明：

- `mappings`：仅收集枚举/开关字段的「编码→含义」映射，键为对应的映射变量名（与 `template` 中一致），空编码项自动剔除；
- `template`：占位表达式而非当前值，工程执行时按实时上报状态渲染；
- 若无任何可生成内容（无字段同时满足「填写显示名 + 选值类型」），提示运营先完成配置，不写回。

## 7. 数据存储

- 生成的运行时配置 JSON 通过 `onDone(out)` 回调写回草稿 `draft.runtime`，并同步更新文本框；点「确定」后写入 `AC.toolRuntimeConfig[行id]`；
- 弹窗草稿保存在 `AC.deviceStateDraft[行id]`；
- 相关配置随智能体配置持久化（`AC.toolRuntimeConfig` 已纳入智能体配置键；草稿 `deviceStateDraft` 目前为运行态缓存）。

## 8. 边界与异常

- JSON 解析失败：提示「JSON 解析失败」并中断；
- `deviceId` / `token` 未填：提示「请先填写 deviceId 和 token」，不发起拉取；
- 枚举当前值未匹配到映射：配置态提示「（未匹配）」，供运营补全映射项；
- 生成时无可写回内容：提示「暂无可生成内容，请先填写显示名并选择值类型」，不写回。

## 9. 验收要点

1. 工具配置面板入口位于「编写教程」左侧，名称为「工具配置」（纯文字无图标）；打开面板自动选中第一个工具（蓝色高亮+右侧详情），无工具时右侧展示空态提示；
2. 面板采用草稿编辑态：编辑先写入 draft，点「确定」经校验（名称必填+工具必选，不通过红字提示）后提交到 `AC.usedTools`，未确定切走则丢弃；确定后保持编辑态；取消回落到第一个工具；
3. 已添加工具行 `AC.usedTools` 为对象数组 `[{id, name, desc, tool}]`，行 id 由 `acGenToolId()` 生成；描述为空时点确定自动填入所选工具默认描述；
4. 运行时配置区始终展示；点击「解析并配置翻译」调用 `acDeviceStateModal(rowId, onDone, dispNameArg)`，回调式写回草稿 `draft.runtime`；
5. 填写 `deviceId`/`token` 后点击「获取上行状态」，上行 JSON 能按树形结构逐字段解析，嵌套可折叠，无价值字段与父节点自动禁用；
6. 各值类型（枚举/数值/开关/文本/数组）生成的 Jinja2 表达式正确，枚举/开关映射可增删并实时命中提示；
7. 点击「生成翻译」通过 `onDone(out)` 回调正确写回 `{postHandler:'templateRender', templateRender:{mappings, template}}` 结构到草稿 runtime，点确定后同步 `AC.toolRuntimeConfig[行id]`；
8. 点过一次「获取上行状态」后，再次打开同一工具行弹窗能回填 `deviceId`/`token`/上行 JSON 与表格配置（草稿按行 id 持久化）；
9. 工程执行时能用实时状态渲染 `template`（配合 `mappings`），输出模型可理解的自然语言文本。
