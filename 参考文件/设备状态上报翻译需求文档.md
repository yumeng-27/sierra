# 设备上行状态翻译 需求文档

## 1. 背景与问题

在语音硬件（AIoT）场景下，智能体需要「查询设备当前状态」并把结果喂给大模型，用于回答用户（如「我的床现在是什么模式？」「音量多大？」）。

调用设备状态查询工具（如 `iot_get_device_shadow` / 获取设备影子状态）后，设备回的是一段**原始上行状态 JSON**，例如：

```json
{
  "success": true,
  "code": 200,
  "message": "操作成功",
  "data": {
    "bedsteadStatus": 2,
    "underBedLight": 1,
    "volume": 60,
    "mattress": { "left": { "monitor": { "heartRate": 66 } } }
  },
  "timestamp": 1785334704485
}
```

**核心痛点**：这份 JSON 是面向设备协议的裸数据，模型无法理解其业务含义——

- 字段名是英文/缩写（`bedsteadStatus`、`underBedLight`），模型不知道对应什么功能；
- 枚举是编码（`bedsteadStatus: 2`），模型不知道 `2` 代表「平躺模式」；
- 夹杂大量无业务价值的协议外壳字段（`success`、`code`、`message`、`timestamp`），干扰模型判断。

若直接把原始 JSON 拼进提示词，模型的理解准确率低、易产生错误回答。因此需要在数据进入模型前，**把上行状态翻译成模型可理解的自然语言文本**。

## 2. 目标

- 将设备上行状态 JSON 翻译为一段模型友好的自然语言状态描述；
- 翻译规则由运营人员在配置阶段一次性配置，工程执行时按实时上报值自动渲染；
- 翻译能力**独立于指令集**，只消费上行数据，不与下行控制契约耦合。

## 3. 概念澄清（架构约束）

| 概念 | 含义 | 数据方向 |
| --- | --- | --- |
| 指令集 | 下发给设备的控制契约（写设备） | 下行数据 |
| 接口返回 | 设备实际上报的状态 | 上行数据 |

**约束**：状态翻译只处理「上行数据」，须独立于指令集单独配置，不复用指令集的字段定义。

## 4. 实现方式

在**调用工具**能力中，为支持状态上报的工具增加一项「运行时配置」。运行时配置存放该工具执行时的额外处理规则（本需求即：状态码转译模板、字段映射等）。

具体交互：
- 在「工具执行」层 → 工具详情中，若工具支持运行时配置（`hasRuntimeConfig`），展示「运行时配置」文本框，并提供「解析并配置翻译」入口；
- 点击「解析并配置翻译」，打开**设备状态翻译配置弹窗**；
- 运营配置完成后，生成的翻译模板**写回**该工具的运行时配置文本框；
- 工程侧在工具执行时读取运行时配置模板，用本次实际上报的状态值渲染，得到翻译后的文本再喂给模型。

## 5. 配置流程（弹窗内两步）

### 步骤 1：查看并解析上行 JSON
- 输入 `deviceId` 和 `token`（必填），点击「刷新并解析」拉取该设备的实时上行状态；
- 上行 JSON 支持手动编辑（便于调试/补充样例）；
- 点击解析后进入步骤 2。

### 步骤 2：解析后配置表格
解析结果以**树形表格**逐字段展示，支持嵌套对象的折叠/展开。每个叶子字段可配置：

| 列 | 说明 |
| --- | --- |
| 上行字段 | 字段的完整点路径（如 `data.mattress.left.monitor.heartRate`），父节点可折叠 |
| 原始值 | 本次上报的实际值，供配置时参考 |
| 标识含义（显示名） | 运营填写的业务名称，如「预设模式」「床底灯」 |
| 值类型 | 枚举 /数值 / 开关 / 文本 / 数组 |
| 枚举映射 / 翻译结果 | 值类型为枚举/开关时，配置「编码 → 含义」映射（如 `2 → 平躺模式`）；数值/文本/数组直接取值 |

**无业务价值字段**：`success`、`code`、`message`、`timestamp` 等协议外壳字段自动置灰，不可配置、不参与翻译。

## 6. 翻译模板生成规则（写回内容）

点击「生成翻译并写回」，按每个已配置字段生成 Jinja2 模板表达式，拼成一行状态描述写回运行时配置：

- **数值 / 文本 / 数组**：直接取值 → `{{ data.xxx }}`
- **枚举 / 开关**：走映射变量 → `{{ data_xxx_map[data.xxx | string] }}`（映射变量名将点路径的 `.` 替换为 `_`，避免 Jinja 变量名非法）

最终写回格式（示例）：

```
> **当前设备状态**：预设模式={{ data_bedsteadStatus_map[data.bedsteadStatus | string] }} 床底灯={{ data_underBedLight_map[data.underBedLight | string] }} 音量大小={{ data.volume }}
```

说明：
- 模板中是**占位表达式**而非当前值，工程执行时按实时上报状态渲染；
- 仅「已填写显示名且已选值类型」的字段会写入模板；
- 若无任何可生成内容，提示运营先完成配置。

## 7. 数据存储

- 翻译模板写回到对应工具的运行时配置（`data-tool-runtime`）；
- 相关配置随智能体配置持久化。

## 8. 边界与异常

- JSON 解析失败：提示「JSON 解析失败」并中断；
- `deviceId` / `token` 未填：提示先填，不发起解析；
- 枚举当前值未匹配到映射：配置态提示「（未匹配）」，供运营补全映射项。

## 9. 验收要点

1. 支持运行时配置的工具能进入「设备状态翻译配置」弹窗；
2. 上行 JSON 能按树形结构逐字段解析，嵌套可折叠，无价值字段自动禁用；
3. 各值类型（枚举/数值/开关/文本/数组）生成的 Jinja2 表达式正确；
4. 生成的翻译模板正确写回运行时配置文本框；
5. 工程执行时能用实时状态渲染模板，输出模型可理解的自然语言文本。
