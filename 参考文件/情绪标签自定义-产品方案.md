# 情绪自定义能力升级 — 产品方案

## 一、现状

1. **自定义情绪只能从 23 种里选**：选择「自定义情绪标签」后，用户写的情绪识别提示词仍要受系统 23 个预置情绪的白名单校验，超出范围的情绪写了也不生效。
2. **情绪映射表写死在后台**：「情绪名称 → 下发标识 EMOTION → 表情 EMOTION_EMOJI」的对应关系固化在服务端代码里，前台不可见、不可改、不可增删。用户不知道自己写的情绪会下发成什么标识，也无法按自己设备的表情资源调整标识与 Emoji。

结果：所谓「自定义」只是在固定清单里挑选，设备侧想做差异化表情动画必须提研发需求改后台。

## 二、需要干什么

两件事，只做这两件：

1. **放开 23 种限制**：自定义模式下情绪识别提示词可自由编写，不校验情绪词白名单。
2. **映射表前台化**：把后台写死的情绪映射表搬到前台，可见、可改、可删、可新增。默认预置 7 条，其余标准情绪由用户自行新增。

**关键约束：提示词与映射表两部分不做任何系统级关联与强校验。** 平台不校验提示词里的情绪词是否出现在映射表中，也不反向校验、不自动同步。一致性由用户自己把握，平台只在界面上说清两者关系与后果。

## 三、交互方案

### 3.1 入口与模式选择

智能体配置 → 策略列表 → 「情绪策略」→ 打开「情绪策略编辑」抽屉（760px）。

抽屉顶部为情绪定义 radio：

| 选项 | 内容 |
|---|---|
| 系统内置，开箱即用 | 只读展示 7 条默认映射（情绪名称 / 下发标识 / 表情），不可编辑；标题旁同样提供问号说明与右侧「查看下发报文」 |
| 自定义情绪标签 | 展开「情绪识别提示词」+「情绪下发映射」两块内容 |

「自定义情绪标签」旁带问号，hover 气泡：*自定义模式下可自由编写情绪识别提示词，并自行维护情绪下发标识与表情映射。*

策略列表「情绪策略」行显示摘要：模式 + 映射条数 + 下发通道。

### 3.2 情绪识别提示词

- 一个可编辑 textarea，默认带入系统模板（角色设定 + 情绪识别系统 + 7 情绪清单 + 输出要求），用户可整段自由编辑。
- 不限制情绪词范围，不做 23 个情绪的白名单校验。
- 右上角提供 AI 辅助入口。
- 不放说明文案，不提供「恢复系统默认」入口。

### 3.3 情绪下发映射

一张可增删改的表格。标题旁带问号（hover 气泡），右侧为「查看下发报文」。

**表格字段**

| 列 | 说明 | 校验 |
|---|---|---|
| 情绪名称 | 模型识别输出的情绪词，用它匹配本行 | 必填、表内唯一、≤ 8 字 |
| 下发标识（EMOTION） | 设备据此播放本地表情动画 | 必填、表内唯一、`^[a-z][a-z0-9_]{0,31}$` |
| 表情（EMOTION_EMOJI） | 随事件下发的字符表情，设备可直接显示 | 选填，单个 Emoji，点击弹出表情选择器 |
| 操作 | 删除本行 | — |

底部为「+ 新增情绪」与「共 N 条」。

**默认预置 7 条**

| 情绪名称 | 下发标识 | 表情 |
|---|---|---|
| 平静 | peace_1 | 😌 |
| 开心 | happy_1 | 😊 |
| 恐惧 | fear_1 | 😨 |
| 悲伤 | sorrowful_1 | 😭 |
| 厌恶 | hate_1 | 😒 |
| 愤怒 | angry_1 | 😠 |
| 震惊 | shock_1 | 😲 |

**行为**

- 任意一行的名称 / 标识 / Emoji 均可修改，可删除；「+ 新增情绪」追加空行。
- 标识不在 23 个标准标识内时，打 ⚠ 黄标提示「自定义标识，需设备固件支持，建议先用调试窗验证」，**只提示不拦截**。
- 不提供「恢复默认」入口，不放顶部 banner 说明。

**问号气泡文案**（330px 深色浮层，两段）

> 情绪名称用于匹配模型识别出的情绪；下发标识 EMOTION 与表情 EMOTION_EMOJI 会随情绪事件下发给设备，支持设备按标识播放对应表情动画。
>
> 提示词中规定的情绪名称，需与本表中的情绪名称一一对应，否则无法正确下发情绪标签和表情。

### 3.4 情绪下发通道

checkbox，必选至少一项：

| 选项 | 说明 |
|---|---|
| 表情 | 将识别到的情绪下发至设备，驱动设备表情的变化 |
| 语音语调 | 将识别到的情绪同步至 TTS 合成，使语音音调随情绪自然变化 |

### 3.5 弹层形态

「选择表情」(460px) 与「下发报文示例」(560px) 均为**抽屉内弹层**：挂在抽屉面板内部、absolute 铺满抽屉，遮罩 rgba(0,0,0,0.28)，不全屏遮挡页面，关闭后回到抽屉编辑态。

「查看下发报文」在**两种模式下都提供**：系统内置模式取默认映射首条作为示例，自定义模式取当前表格中首条已填完整的映射作为示例。

### 3.6 保存校验

- 名称 / 标识必填、表内唯一、标识符合格式；任一不满足则定位到首个错误行并阻断保存。
- 下发通道至少勾选一项。
- 标识非标准仅黄标提示，不阻断。

## 四、下发协议

```json
"eventData": {
  "msg": "表情情绪事件",
  "data": { "args": { "EMOTION": "happy_1", "EMOTION_EMOJI": "😊" } },
  "type": "CALL_SKILL_EVENT"
}
```

- Emoji 为空时不下发 `EMOTION_EMOJI` 字段（不下发空串）。
- 开启「语音语调」时按旧逻辑补发 `TTS_EMOTION`。
- 模型输出的情绪名在映射表中找不到时，不下发情绪事件（📌 待确认：是否需要固定兜底为 `peace_1`）。

## 五、数据结构

`AC.emotionConfig`，按智能体维度隔离存储：

```json
{
  "mode": "custom",
  "prompt": "# 角色设定 ...",
  "items": [
    { "name": "开心", "code": "happy_1", "emoji": "😊" },
    { "name": "困倦", "code": "sleepy_1", "emoji": "😴" }
  ],
  "channels": { "expression": true, "tts": false }
}
```

## 六、存量兼容

- 系统内置模式：不变，7 条映射只读。
- 已配自定义提示词的存量应用：提示词原样保留进「情绪识别提示词」；映射表自动预填其原有的标准映射，行为与现状一致，用户不动就不会有任何变化。

## 七、反思

🎯 **关键假设**：模型输出的情绪名与映射表「情绪名称」做精确字符串匹配（📌 待确认是否需要支持同义词 / 模糊匹配）。

⚠️ **最大风险**：两部分解耦后，「提示词写了 X 但表里没有 X」会变成静默无表情。缓解手段：映射表说明文案 + 调试窗验证，不加系统级强校验。

💡 **可沉淀能力**：「语义名 → 端侧标识 + 展示资源」映射表是通用组件，可复用于动作、灯效、音效等所有「模型语义 → 端侧枚举」场景。
